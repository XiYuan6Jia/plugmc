# 商业街：与经济系统实时联动

主城西南角的商业街。摊位不是摆设，而是经济系统的实时投影 —— 谁在卖什么、卖多少钱，
走过去看摊位的招牌和货台就知道。

```
经济系统（economy 插件）        bazaar 插件                 主城 hub 维度
  market / auction / order  ──►  TradeBoard（只读）  ──►  摊位建筑 + 人偶 + 招牌 + 货台
        ▲                                                     │
        └────────────── 玩家点招牌开枪界面 ◄───────────────────┘
```

---

## 1. 它做什么

| 现象 | 说明 |
|---|---|
| 有人挂了单 | 40 tick（2 秒）内自动出现一个摊位，摊主的人偶站在那里 |
| 同一个人挂十件货 | 只占**一个**摊位，招牌列出全部交易项（超出 `sign-max-deals` 的折成「…还有 N 项」） |
| 交易全部结束 | 摊位自动撤除，装饰方块逐格还原成原来的样子 |
| 官方摊位 / 银行 / 活动摊 | 常驻，与玩家交易无关，插件一启用就摆出来 |
| 玩家下线 | 摊位留着（交易还在），人偶换成离线皮肤 |

## 2. 三条硬规则

**一玩家一摊**：分配单位是玩家名，不是交易项。

**位置稳定**：摊位号 = `Math.floorMod(名字小写.hashCode(), 摊位数)`，冲突时向后顺延。
同一个人下次摆摊还回老地方，玩家能记住「我的摊在西边第三家」。

**装饰随机但不上蹿下跳**：只在**新占用**时抽一次，之后每 40 tick 的刷新不动装饰 ——
否则摊主看着自己的摊每 2 秒换一身衣服。解放后重新上摊会重新抽。

## 3. 摊位怎么摆

每个摊位 5×3 格，`floor-y` 是广场地面那一层：

```
y+4   ███████████████  顶棚（canopy）
y+3   ██           ██
y+2   ██    招牌    ██
y+1   ██  人偶  [货台×3] ██
y     ███████████████  地毯（carpet）
```

- 柱子两角：`pillar`
- 货台三格：`base`，上面浮着三个自转的 `ItemDisplay`
- 人偶：26.3 原生的 `minecraft:mannequin`，`setProfile()` 用摊主的真实皮肤

## 4. 配置（`plugins/bazaar/config.yml`）

```yaml
world:
  name: hub
  floor-y: 64

refresh:
  ticks: 40            # 多久跟经济系统对一次账

stalls:
  fixed:               # 常驻摊位，装饰按顺序取（不随机）
    bank:
      kind: bank
      x: -40
      z: 28
    official:
      kind: official
      x: -54
      z: 28
    event:
      kind: event
      x: -30
      z: 28
  player:              # 玩家摊位区，按 spacing 打格子（当前 6×4 = 24 位）
    x0: -58
    z0: 34
    x1: -26
    z1: 58
    spacing: 6
    facing: 180
  sign-max-deals: 6    # 招牌最多列几条，调大会往上长，别压到人偶
  decor:               # 每套四个材质：底座 / 柱 / 顶棚 / 地毯
    - id: quartz
      base: minecraft:stone_bricks
      pillar: minecraft:quartz_pillar[axis=y]
      canopy: minecraft:smooth_quartz
      carpet: minecraft:white_wool
    ...
```

## 5. 命令

| 命令 | 作用 |
|---|---|
| `/bazaar status` | 维度、地面高度、已占摊位 / 总数、装饰套数、刷新间隔 |
| `/bazaar list` | 当前所有摊主与他们的交易 |
| `/bazaar check` | 自检：摆一个假摊 → 刷新 → 解放 → 核对 245 格是否原样 |
| `/bazaar rebuild` | 全部撤掉重摆 |
| `/bazaar reload` | 重读配置（会重建固定摊位） |

## 6. 数据从哪来

`economy` 插件注册了一个只读服务：

```java
public interface TradeBoard {
    List<AuctionListing> auctions();
    List<MarketListing> markets();
    List<BuyOrder> orders();
}
```

`bazaar` 通过 `Bukkit.getServicesManager().load(TradeBoard.class)` 拿它，**不缓存、不落盘**。
每次刷新都重新问一遍经济系统，所以拍卖被一口价买走、挂单被取消，摊位会在 2 秒内跟着变。

> bazaar 自己**没有任何交易状态**。关掉它、删掉配置文件，经济系统毫发无损；
> 重新启用时摊位会按当时的经济数据自动重建 —— 这一点在多次重启中反复验证过。

## 7. 踩过的坑

**hub 的 `deny-mob-spawn` 曾拦住所有实体。** `HubListener.onSpawn` 原来无条件
`event.setCancelled(true)`，而 armor_stand / mannequin 这类也走 `CreatureSpawnEvent` ——
连插件自己 `world.spawn()` 造的人偶都被取消，`Mannequin mannequin = world.spawn(...)`
返回的实体从未进世界。现在只拦 `isNaturalSpawn()` 列出的自然刷怪来源。

**`data get block` 读不了普通方块。** 它只对方块实体（箱子、告示牌）有效，普通方块一律回
`The target block is not a block entity`。要确认摊位位置摆的是什么，用 `/probeblock`。

**`data get entity @e[...]` 多于一个实体直接报错。** 要用
`as @e[type=minecraft:mannequin] run data get entity @s Pos`。

**`execute ... run positioned ...` 是非法语法。** `positioned` 是 `execute` 的子命令，
不能跟在 `run` 后面。回显里带 `<--[HERE]` 说明命令**根本没执行**，不能读成「查询结果为空」。

**换 jar / 换数据包必须重启或 reload**，否则服务端一直用缓存里的旧内容。

## 8. 验证记录

自检 7/7：柱子、人偶、招牌、货台、实时刷新、撤除、还原（245 格逐格比对）。

真实交易走过的完整链路（测试服实测）：

1. `ShopTester` 挂单 `Diamond ×32 @12.50` → 2 秒内 22 号摊位立起，人偶出现在 `-25.5, 65, 41.5`
2. 同一个人再挂拍卖和求购 → 同一个摊位，招牌变成「售卖 1 · 拍卖 1 · 求购 1」
3. `Buyer2` 一口价买走拍卖 → 该摊主再无活跃交易 → 摊位立即撤除，装饰 8 格全部还原成 air
4. 三笔全取消后重新挂单 → 装饰从「下界黑石」换成别的方案（重抽生效）
