# 商业街：与经济系统实时联动

主城西南角的商业街。摊位不是摆设，而是经济系统的实时投影 —— 谁在卖什么、卖多少钱，
走过去看摊位的招牌和货台就知道。

```
经济系统（economy 插件）        bazaar 插件                 主城 hub 维度
  market / auction / order  ──►  TradeBoard（只读）  ──►  摊位建筑 + 人偶 + 招牌 + 货台
        ▲                                                     │
        └────────────── 玩家右键人偶开界面 ◄─────────────────────┘
```

---

## 1. 它做什么

| 现象 | 说明 |
|---|---|
| 有人挂了单 | 40 tick（2 秒）内自动出现一个摊位，摊主的人偶站在那里 |
| 同一个人挂十件货 | 只占**一个**摊位，招牌列出全部交易项（超出 `sign-max-deals` 的折成「…还有 N 项」） |
| 交易全部结束 | 摊位自动撤除，装饰方块逐格还原成原来的样子 |
| 官方摊位 / 银行 / 活动摊 | 常驻，与玩家交易无关，插件一启用就摆出来 |
| 玩家下线 | 摊位留着（交易还在），人偶换成离线皮肤 |
| 右键人偶 / 货台 | 直接打开摊主的交易界面（只有一种就直接进，有多种先弹选择屏） |

## 2. 三条硬规则

**一玩家一摊**：分配单位是玩家名，不是交易项。

**位置稳定**：摊位号 = `Math.floorMod(名字小写.hashCode(), 摊位数)`，冲突时向后顺延。
同一个人下次摆摊还回老地方，玩家能记住「我的摊在西边第三家」。

**装饰随机但不上蹿下跳**：只在**新占用**时抽一次，之后每 40 tick 的刷新不动装饰 ——
否则摊主看着自己的摊每 2 秒换一身衣服。解放后重新上摊会重新抽。

## 3. 摊位怎么摆

每个摊位 5×3 格，`floor-y` 是广场铺装**最上面那一层**（也是玩家脚下的站立面，hub 里是 64）：

```
y+4   ███████████████  顶棚（canopy）
y+3   ██           ██
y+2   ██  人偶  [货台×3] ██
y+1   ██  ░░░░░░      ██   地毯（carpet）· 货台（base）
y     ███████████████     广场铺装（不动）
            ↓
         招牌浮在这里（摊位正前方，离地 3.4 格）
```

- 柱子两角：`pillar`，从 `y+1` 长到 `y+3`
- 货台三格：`base`，在 `y+1` 最前一排，上面浮着三个自转的 `ItemDisplay`
- **地毯铺在 `y+1`**（铺装上面一层），只铺 `z0+0`、`z0+1` 两排 —— 最前一排 `z0+2` 是货台，同层会互相覆盖
- 人偶：26.3 原生的 `minecraft:mannequin`，`setProfile()` 用摊主的真实皮肤；
  脚底取 `y+1` 那格的碰撞盒顶面，站地毯上就是 `floor-y + 1.0625`，没地毯就回落到 `floor-y + 1.0`
- **招牌挂在摊位占地之外**（`y+3.4`、`z0+DEPTH+0.2`）。原来挂在摊位内部 `y+3.7`，
  顶棚在 `y+4`，招牌以自身中心上下摊开 —— 列到六七条交易时上半截直接嵌进顶棚方块里看不见。

## 4. 配置（`plugins/bazaar/config.yml`）

```yaml
world:
  name: hub
  floor-y: 64

refresh:
  ticks: 40            # 多久跟经济系统对一次账

stalls:
  fixed:               # 常驻摊位，装饰按顺序取（不随机）；三个摊位沿 x 等距 10 格
    official:
      kind: official
      x: -52
      z: 28
    bank:
      kind: bank
      x: -42
      z: 28
    event:
      kind: event
      x: -32
      z: 28
  player:              # 玩家摊位区，按 spacing 打格子（当前 6×4 = 24 位）
    x0: -58
    z0: 34
    x1: -26
    z1: 58
    spacing: 6
    facing: 180
  sign-max-deals: 6    # 招牌最多列几条，调大会往上长，别压到人偶
  decor:               # 每套四个材质：底座 / 柱 / 顶棚 / 地毯
    - id: quartz
      base: minecraft:stone_bricks
      pillar: minecraft:quartz_pillar[axis=y]
      canopy: minecraft:smooth_quartz
      carpet: minecraft:white_carpet
    ...
```

## 5. 怎么用（玩家视角）

**右键摊位的人偶或货台，直接打开对应的交易界面。**

- 摊主只有一种交易 → 直接进那个界面（市场 / 拍卖行 / 收购订单）
- 摊主同时在卖、在拍、在收 → 先弹一个选择屏，点头上的按钮进对应界面
- 点固定摊位（银行 / 官方商店 / 活动摊）的人偶 → 直接开银行或系统商店

界面本身用的是经济系统原有的那几个，bazaar 只是把入口搬到人身上 ——
买、出价、交货的校验和原来一模一样，不存在"商业街买的货不走账"这种情况。

## 6. 命令

| 命令 | 作用 |
|---|---|
| `/bazaar status` | 维度、地面高度、已占摊位 / 总数、装饰套数、刷新间隔 |
| `/bazaar list` | 当前所有摊主与他们的交易 |
| `/bazaar check` | 自检：摆一个假摊 → 刷新 → 解放 → 核对 245 格是否原样 |
| `/bazaar rebuild` | 全部撤掉重摆 |
| `/bazaar reload` | 重读配置（会重建固定摊位） |

## 7. 数据从哪来
`economy` 插件注册了一个只读服务：

```java
public interface TradeBoard {
    List<AuctionListing> auctions();
    List<MarketListing> markets();
    List<BuyOrder> orders();
}
```

`bazaar` 通过 `Bukkit.getServicesManager().load(TradeBoard.class)` 拿它，**不缓存、不落盘**。
每次刷新都重新问一遍经济系统，所以拍卖被一口价买走、挂单被取消，摊位会在 2 秒内跟着变。

> bazaar 自己**没有任何交易状态**。关掉它、删掉配置文件，经济系统毫发无损；
> 重新启用时摊位会按当时的经济数据自动重建 —— 这一点在多次重启中反复验证过。

## 8. 踩过的坑

**人偶头上会叠出两个名字。** `minecraft:mannequin` 出厂自带一段 `description`
（原版语言键 `entity.minecraft.mannequin.label` = `NPC`），默认可见；再调 `setCustomName`
就变成「银行」+「NPC」两行叠在一起。修法是 `entity.setDescription(null)` ——
`CraftMannequin.setDescription(null)` 内部走的就是 `setHideDescription(true)`，
之后 `data get entity @s description` 直接查不到该字段。

**招牌不能用 `Billboard.CENTER` 顶着顶棚。** TextDisplay 以自身中心向上下摊开，
离顶棚只剩 0.3 格时，列到六七条交易上半截就埋进方块里了。挪到摊位占地之外最省事。

**地毯必须铺在 `floor-y + 1`，不能铺在 `floor-y`。** `floor-y` 那一层就是广场铺装本身，
也是玩家脚下的站立面（hub 里是 64，头顶站立高度 65.0）。第一版把地毯写在这一层，等于把地面
挖掉换成地毯 —— 地毯只有 1/16 格高，站在上面的人偶脚底变成 `64.0625`，比周围地面低将近一格，
从外面看只剩一个头露在地面上。改到 `floor-y + 1` 之后，铺装完整保留，地毯顶面
`floor-y + 1.0625`，只比周围地面高 1/16 格，视觉上完全平贴。

**人偶的脚底要问服务端要碰撞盒顶面，不能写死。** `Block.getBoundingBox().getMaxY()` 给出
脚下那格真实的顶面（地毯 `65.0625`、整方块 `66.0`、空气 `0` 时回落到 `floor-y + 1.0`）。
自检里对应一项「人偶站在地毯上」，判据是两个高度差 `< 0.02`。

**hub 的 `deny-mob-spawn` 曾拦住所有实体。** `HubListener.onSpawn` 原来无条件
`event.setCancelled(true)`，而 armor_stand / mannequin 这类也走 `CreatureSpawnEvent` ——
连插件自己 `world.spawn()` 造的人偶都被取消，`Mannequin mannequin = world.spawn(...)`
返回的实体从未进世界。现在只拦 `isNaturalSpawn()` 列出的自然刷怪来源。

**`data get block` 读不了普通方块。** 它只对方块实体（箱子、告示牌）有效，普通方块一律回
`The target block is not a block entity`。要确认摊位位置摆的是什么，用 `/probeblock`。

**`data get entity @e[...]` 多于一个实体直接报错。** 要用
`as @e[type=minecraft:mannequin] run data get entity @s Pos`。

**`execute ... run positioned ...` 是非法语法。** `positioned` 是 `execute` 的子命令，
不能跟在 `run` 后面。回显里带 `<--[HERE]` 说明命令**根本没执行**，不能读成「查询结果为空」。

**换 jar / 换数据包必须重启或 reload**，否则服务端一直用缓存里的旧内容。

**端到端验证前先确认人不是死的。** 死亡状态（`Health: 0.0f`、`DeathTime > 0`）下
`Player.teleport()` 一律返回 false，表现出来只是"传送没生效"，很难联想到死亡。
`/asheal <玩家>` 会先 `spigot().respawn()` 再拉满血。

**RCON 线程不是主线程。** 跨维度 `teleport()` 必须在主线程做（`runTask`），否则直接返回 false。

**`/hub` 会被 HuskHomes 的 `/spawn` 别名抢走。** 传送主城实测要走 `astp`（Bukkit API），
不要指望命令层。

## 9. 验证记录

自检 **10/10**：柱子、人偶、名牌只剩一份名字、**人偶站在地毯上**、招牌、货台、实时刷新、
撤除、还原（245 格逐格比对）、**固定摊位间距一致**。

真实交易走过的完整链路（测试服实测）：

1. `ShopTester` 挂单 `Diamond ×32 @12.50` → 2 秒内 22 号摊位立起，人偶出现在 `-25.5, 65.0625, 41.5`
2. 同一个人再挂拍卖和求购 → 同一个摊位，招牌变成「售卖 2 · 拍卖 1 · 求购 1」
3. `Buyer2` 一口价买走拍卖 → 该摊主再无活跃交易 → 摊位立即撤除，装饰 8 格全部还原成 air
4. 三笔全取消后重新挂单 → 装饰从「下界黑石」换成别的方案（重抽生效）

右键链路的验证（`/asclick` 合成真事件，走完整监听器注册链）：

| 点哪里 | 期望 | 实测界面 |
|---|---|---|
| 只有挂单的摊主 | 直接进市场 | 玩家市场 (1/1)，54 格 |
| 挂单 + 拍卖 + 求购 | 弹选择屏 | 「ShopTester 的交易」，9 格 |
| 选择屏槽位 0 | 市场 | 玩家市场 (1/1) |
| 选择屏槽位 2 | 拍卖行 | 拍卖行 (1/1) |
| 选择屏槽位 4 | 收购订单 | 收购订单 (1/1) |
| 银行摊位人偶 | 开银行 | 建材银行，54 格 |
| 官方商店人偶 | 开系统商店 | 系统商店，45 格 |

线上（minekuai `bb911bbb`）复验：`bazaar check` **10/10**、
四个人偶 `hide_description` 全部 `1b`、四个人的 `Pos` 全部 `y = 65.0625`（踩在地毯顶面）、
三块固定摊位人偶 `x` 为 `-49.5 / -39.5 / -29.5`（等距 10）、
四块招牌全部落在 `y = 67.4`（= 地面 64 + 3.4）、`z` 比摊位中心外推 3.2 格 —— 不在顶棚覆盖范围内。
方块层实测（`/probeblock hub`）：固定摊位 `-51 65 28 = white_carpet`、`-51 64 28 = smooth_quartz`（铺装保留）、
`-51 66 28 = air`；玩家摊位 `-44 65 41 = green_carpet`、`-44 64 41 = smooth_quartz`、`-44 66 41 = air`。
