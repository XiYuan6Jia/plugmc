## 一、两条链路各管什么

| 链路 | 用途 | 入口 |
|---|---|---|
| **面板 API** `https://api.minekuai.cn/panel/client-api` | 读实例状态、读日志、**发控制台命令**、重启/停止 | `.local/minekuai.env` |
| **SFTP** `q1.minekuai.cn:10001` | 上传 jar / zip、删旧版本、备份线上数据 | `.local/sftp.env` |

关键事实（实测，别按直觉猜）：

- API **没有列目录端点**：`/files`、`/files/list`、`/resources` 全部返回 `{"code":404,"msg":"No endpoint ..."}`。列目录必须走 SFTP。
- API **可以按具体路径读文件**：`GET /files/contents?file=/server.properties` 返回真实内容——`server.properties` 和 `logs/latest.log` 都能这样读。
- API **可以发控制台命令**：`POST /command` + `{"command": "..."}`，回显落在 `latest.log` 里。**这是验证数据包/插件是否真生效的唯一手段**（`datapack list`、`plugins`、`version`、`eco selftest` 都是这么跑出来的）。
- API 的错误响应**也是 HTTP 200**，真实状态在 body 的 `code` 字段——所以不能只看状态码。

## 三、部署插件

```powershell
# 只检查不部署：读线上 latest.log，看现存插件是否都在 Enabling 列表里
python scripts/deploy_paper.py --check-only

# 真部署：构建 → 上传 jar → 备份线上数据 → 重启 → 校验 Enabling
python scripts/deploy_paper.py --plugin economy

# 复用已有 jar 不重新构建
python scripts/deploy_paper.py --plugin economy --skip-build

# 只上传不重启（下次重启生效）
python scripts/deploy_paper.py --plugin economy --upload-only

# 前 60 秒全服倒计时公告（无人在线自动跳过）
python scripts/deploy_paper.py --plugin economy --announce-seconds 60
```

脚本行为要点：

- 只删本次要部署的 `<id>-*.jar` 旧版本，不碰其它插件。
- 部署前把线上 `plugins/<id>/` 下载到 `.local/backup/remote-<时间>/`（`--no-remote-backup` 可跳过）。
- 重启后要求**先离开 running 或日志已变化**才认 `Done (`，避免被重启前那份日志骗过。
- 校验方式是日志里出现 `Enabling <插件名>` 或 `[<插件名>]`。

## 四、部署数据包

```powershell
# 构建 + 备份线上同名旧包 + 上传 zip 到 world/datapacks/ + 重启 + 校验
python scripts/deploy_datapack.py --pack plugmc-demo

# 只检查：读日志 + 发 /datapack list
python scripts/deploy_datapack.py --check-only

# 只上传不重启
python scripts/deploy_datapack.py --pack plugmc-demo --upload-only

# 明确跳过覆盖前备份（不建议）
python scripts/deploy_datapack.py --pack plugmc-demo --no-backup
```

与插件部署的区别：

- 数据包以 **zip 形式**放 `world/datapacks/`，服务端启动时自动发现（日志：`Found new data pack file/plugmc-demo.zip, loading it automatically`）。
- 上传前会**先把同名旧 zip / 旧文件夹备份到 `.local/backup/datapacks-<时间>/`**，然后再清掉——两者不能共存，共存时哪个生效取决于加载顺序。
- 校验用 `/datapack list`，应看到 `[file/plugmc-demo.zip (world)]`。

**已验证的坑**：`datapack list` 显示已启用 ≠ 函数真的跑了。唯一可信判据是日志里能看到数据包自己 `say` 的回执，或者手动 `function <命名空间>:load` 能跑通。

## 五、线上数据备份（不可清空，必须可回滚）

线上 `plugins/` 与 `world/` 里是**另一位开发者和真实玩家玩出来的数据**，任何时候都不能清空。两个部署脚本都已内置备份，但要知道它们各自备了什么：

| 脚本 | 备份时机 | 备份内容 | 落到哪 |
|---|---|---|---|
| `deploy_paper.py` | 上传 jar **之前** | 目标插件在 `plugins/<id>/` 下的全部文件（状态、账本、配置、插件自己的快照） | `.local/backup/remote-<yyyymmdd-HHMMSS>/` |
| `deploy_datapack.py` | 上传 zip **之前** | `world/datapacks/` 里与本次同名的旧 zip / 旧目录 | `.local/backup/datapacks-<yyyymmdd-HHMMSS>/` |

**关键实现细节（踩过）**：线上容器里的文件属主是 root，SFTP `get` 会直接报 `PermissionError: [Errno 13] permission denied`。所以备份的下载动作走**面板 API** `/files/contents`（它能读二进制原文），SFTP 只用来列目录。

实测备份下来的 `economy`（2026-11-11 16:19）：

```
economy/config.yml          89 B
economy/goods.yml      105,486 B
economy/state.json       2,714 B   ← schemaVersion 2 / lastSeq 675 / accounts 11 个
economy/ledger/2026-11.jsonl  186,746 B
economy/backup/state-*.json   14 份自动快照
```

回滚方法：把备份目录里的文件原路传回对应远端目录，再重启实例。

## 七、同步回 GitHub（改动前必查、改动后必推）

固定流程只有两条命令，都走 `scripts/repo_sync.py`——**不要手搓 `git pull`**，它会掩盖另一位开发者的改动。

### 7.1 动手前：查库

```powershell
cd 'C:\Users\16923\Documents\原版服务器插件开发\plugmc'
python scripts/repo_sync.py check
```

输出会给出：本地 HEAD / 远端 sha、本机身份、同步水位、领先落后数、未提交文件数、**按作者归并的远端新提交**、**他人改动了哪些文件**、以及"他人改过的文件 ∩ 本机未提交改动"的冲突风险。落后时以 **exit 1** 退出，视为阻塞——此时不要往下写代码。

### 7.2 拉取他人改动

只有 `check` 报落后时才做，照它给的命令：

```powershell
git stash push -u -m 'wip: <本次改动说明>'
git merge --ff-only origin/main
git stash pop
```

用 `--ff-only`：接不上就说明本地已经和远端分叉，这时候要人来判断，别自动 merge。

### 7.3 改动后：推库

```powershell
python scripts/repo_sync.py push -m "feat(<模块>): <一句话说明>"
```

它做四件事：落后远端时**拒绝执行**（避免覆盖他人提交）→ `git add -A` + commit + `git push origin main` → 再 `fetch` 回读校验必须 `领先/落后 = 0/0` 且远端 sha 前缀匹配 → 通过才写同步水位 `.local/last_sync.json`。

### 7.4 环境事实

- 远端：`https://github.com/XiYuan6Jia/plugmc.git`，分支 `main`
- 协作方：`XiYuan6Jia <2138403788@qq.com>`（另一位开发者）、`blackis555 <169038306+blackis555@users.noreply.github.com>`（本机）
- 凭据：Windows 凭据管理器里的 `git:https://github.com`（**已存在**，可直接 push，不会再弹窗）

首次授权时卡过一次：GCM 的 OAuth 回调是 `http://127.0.0.1:<随机端口>/?code=...&state=...`，后台跑 `git push` 时这个回调窗口拿不到焦点。**解决办法是用户自己在浏览器里完成登录，然后把回调 URL 交回来**，或者在前台终端手动跑一次 `git push` 走完弹窗。
