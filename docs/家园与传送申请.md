# 家园与传送申请

两件事：`/home` 回自己家（本来就归 sethome），以及 `/tpahome` 申请传送到**别人**的家 —— 后者是这次新加的，走 tpa 那套「发申请 → 对方同意 → 读秒 3 秒 → 传送」的流程，和 `/tpa`、`/tpahere` 完全一致。

## 1. 玩家怎么用

| 场景 | 玩家输入 | 说明 |
|---|---|---|
| 回自己家 | `/home` / `/home 名字` | 只有一个家时可以不写名字 |
| 看自己有哪些家 | `/homes` | 每个家后面带 [传送] [删除] |
| 设置家 | `/sethome 名字` | 默认上限 3 个 |
| 申请去**别人**家 | `/tpahome 玩家 家园名` | 对方不写家园名且只有一个家时自动选中 |
| 从菜单点 | Shift+F → 申请传送 → 再点一次切到「申请传送到别人的家」 | 头像下面会列出这个人的家园名 |
| 处理收到的申请 | `/tpaccept 玩家` / `/tpadeny 玩家` | 也可以点聊天里的 [点击接受] / [拒绝] |

申请发出后对方收到：「`X` 想传送到你的家（`base`）： [点击接受] [拒绝]」，60 秒内有效。

## 2. 三条容易踩的行为约定

**家园名不替你猜。** 对方有 2 个以上的家时，`/tpahome 玩家` 会列出名字让你自己指定，不会默认挑一个。理由是「去哪个家」是玩家的意图，猜错了传送落点比让他多打几个字更糟。

**家坐标在接受那一刻才解析。** 申请只记 `homeName`，真正的坐标在对方点「接受」时去查。所以申请发出后、对方接受前，那个家被删掉的话，会得到「`Buyer2` 的家园已不存在，传送申请已取消」，而不是把人送到一个空坐标。

**读秒期间对方还在动的话，落点跟着他走。** `/tpa`、`/tpahere` 的读秒 tick 里每 tick 刷新一次目标位置（`anchorId != null` 时）；`/tpahome` 的目标是固定坐标（`anchorId == null`），不刷新。玩家移动一格或受伤仍然取消读秒 —— 这条和原来一样。

## 3. sethome 侧：只读的 `HomeService`

外部插件不该直接读 `homes.yml`，也不该拿到能改家园的对象。所以 sethome 暴露一个只读服务：

```java
public interface HomeService {
	Location home(UUID owner, String name);   // 没有 / 世界没加载 → null
	List<String> names(UUID owner);
	default boolean has(UUID owner, String name)
	default int count(UUID owner)
	String defaultName();
}
```

取用 `Bukkit.getServicesManager().load(HomeService.class)`。

**只暴露查询，不暴露写入** —— 改家园是 `/sethome`、`/delhome` 的事，走那条路才会做数量上限和命名校验。`home()` 返回 `location.clone()`，调用方改返回值不会污染存储；`HomeServiceImpl` 刻意不缓存，家园数据量很小，现读现回可以省掉「改完家之后还读到旧坐标」这类问题。

## 4. tpa 侧：`TpaRequest` 多了方向和家名

```java
public record TpaRequest(UUID from, String fromName, UUID to, String toName,
                         Direction direction, String homeName, long expiresAt) {
	public enum Direction { TO_TARGET, TO_SENDER, TO_HOME }
}
```

- `TO_TARGET`：`/tpa`，发送者去目标那里
- `TO_SENDER`：`/tpahere`，目标来发送者这里
- `TO_HOME`：`/tpahome`，发送者去目标的某个家

`homeName` 只在 `TO_HOME` 时有意义，为空表示「用那个人的默认家园」。`describe()` 按方向生成给接收方看的那句话。

`TpaManager.request(...)` 在 `TO_HOME` 分支多做四道校验：`allow-home-request` 开关、`tpa.home` 权限、`HomeService` 是否可用（sethome 没装就退回「服务器没开这个功能」）、目标是否真的有那个家。

## 5. 配置

`plugins/tpa/config.yml` 新增一项（其余不变）：

```yaml
# 是否允许 /tpahome 申请传送到别人的家（需要 sethome 插件提供家园数据）
allow-home-request: true
```

`plugins/sethome/config.yml` 没有变化：`max-homes: 3` / `teleport-warmup-seconds: 3` / `teleport-cooldown-seconds: 10` / `deathpoint-enabled: true`。

`/tpahome` 的权限是 `tpa.home`（默认 true），可以在 LuckPerms 里单独关掉而不影响 `/tpa`。

## 6. 验证记录（本机 `server\.testrun`，2026-11-14）

| 用例 | 操作 | 结果 |
|---|---|---|
| 设置两个家 | `Buyer2 sethome base` / `sethome workshop` | `homes` 列出 `base (300.5,61,300.5)`、`workshop (300.5,69,308.5)` |
| 多个家不猜 | `ShopTester tpahome Buyer2` | 「Buyer2 有 2 个家园，请指定一个：base、workshop / 用法：/tpahome Buyer2 <家园名>` |
| 指定家园发申请 | `tpahome Buyer2 base` | 对方收到「ShopTester 想传送到你的家（base）： [点击接受] [拒绝]」 |
| 接受后读秒传送 | `Buyer2 tpaccept ShopTester` | 「传送准备中：3 秒后传送，移动或受伤会取消。」→ 4 秒后「已传送到 Buyer2 的家（base）」，`Pos` 从 `[100.5,61,100.5]` 变成 `[300.5,61,300.5]` |
| 只有一个家时自动选中 | 删掉 workshop 后 `tpahome Buyer2` | 直接发出（`base`），不再要求指定 |
| 家被删的兜底 | 发申请后 `Buyer2 delhome workshop` 再接受 | 「Buyer2 的家园已不存在，传送申请已取消。」玩家原地未动 |
| 拒绝 | `Buyer2 tpadeny ShopTester` | 「Buyer2 拒绝了你的传送申请。」 |
| 原有 `/tpa` 未受影响 | `tpa Buyer2` → 接受 | 「已传送到 Buyer2 身边」，落点 `[300.5,69,308.5]` |
| `/home` 自身传送未受影响 | `/sethome camp` → `/home camp` | 「将在 3 秒后传送到 家园 camp」→「已传送到 家园 camp」 |

线上（`bb911bbb`）部署后复验：`help tpahome` 回 `申请传送到某人的家（对方同意后读秒传送）` / `Usage: /tpahome <玩家> [家园名]` / `Aliases: tphome`；`help home` 仍是 sethome 的「传送回家园」。

## 7. 踩过的坑

- **`/home` 早就有，别再写一个。** sethome 插件已经有 `sethome`/`home`/`delhome`/`homes`/`deathpoint` 五个命令和完整的读秒/冷却/移动取消逻辑，新做一套只会两个插件抢同一个命令。
- **`plugin.yml` 改了必须重启服务器，`/reload` 不会重新注册命令表。**
- **`mc_launch` 起的第二个客户端要和第一个用不同用户名**，否则顶号；两个客户端同时在线才能测「发申请 → 接受」。
- **`astp` 传送前先 `asheal`**：玩家躺在死亡界面时 `teleport()` 恒返回 false。
- **`astp` 的世界名是 Bukkit 的 `world`，不是 `minecraft:overworld`。** `execute in minecraft:overworld` 能用于方块命令，但 `/astp` 走 `Bukkit.getWorld`，传 `overworld` 会回「世界没加载」。
- **别用 PowerShell 管道改仓库里的 Java 文件**（`Get-Content -Raw | -replace | Set-Content` 会按 GBK 读 UTF-8，整份中文变乱码）。用 write/edit 工具。
