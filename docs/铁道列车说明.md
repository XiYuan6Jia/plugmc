# 铁道列车（train 插件）

用拴绳把矿车两两连成一列，车头那台动力矿车烧煤（或踩着通电的动力铁轨）拖着整列走，
按设定好的路线依次经过各个站点，进站自动减速、停在站台前、停够时间再走。

---

## 1. 玩家怎么玩

### 1.1 连接

手持**拴绳**，**按住 Shift** 依次**右键**两台矿车：

```
shift+右键 第一台  →  「已选中一节车厢，再 shift 右键另一台矿车连接。」
shift+右键 第二台  →  「已连接。列车现在有 2 节车厢。」
```

- 连一次**消耗一根拴绳**。
- 再点一次同一台（连着点两下）→ 「已取消选中。」，不扣也不还。
- 创造模式（且 `limits.free-in-creative: true`）不扣也不返还。

### 1.2 规则

| 规则 | 说明 |
|---|---|
| 动力矿车只能挂在两端 | 挂在中间会提示「动力矿车只能挂在列车的最前面或最后面。」 |
| 最多两端各一个动力矿车 | 两端都有就是**双向列车**，到终点自动换另一头当车头往回开 |
| `/train start` 要求车头是动力矿车 | 否则提示「车头必须是动力矿车」 |
| 车厢上限 | `limits.max-cars`，默认 12 |
| 跨重启保留 | 编组写在 `plugins/train/consists.yml`，重启后还在 |

### 1.3 解开

手持拴绳 **shift+右键已经连上的那一节** → 「已解开这一节车厢的连接。」，**还回一根拴绳**。

> 注意顺序：手上有「待连目标」时，右键永远是连第二台；只有手上没目标时，右键已连接的车厢才是解开。

### 1.4 站点与路线（需要 `train.admin`）

站点就是铁轨上的一个方块坐标：

```
/train station create <名字>                  # 站在铁轨上敲，用它脚下那格
/train station create <名字> <世界> <x> <y> <z>   # 控制台用
/train station dwell <名字> <秒>              # 改这个站的停靠时间（默认 8 秒）
/train station list                           # 看所有站点（✔ / ✘：✘ 表示那格已经不是铁轨了）
```

路线是站点的有序列表：

```
/train route create <路线名> <站点1,站点2,...>       # 默认循环
/train route create <路线名> <站点1,站点2,...> false  # 往返（终点掉头）
/train route loop <路线名> <true|false>              # 事后改
/train route add <路线名> <站点>                     # 往末尾加一站
/train route info <路线名>
/train route list
```

### 1.5 开与停

```
/train start <路线名>    # 站在列车任意一节旁边
/train stop              # 站在列车旁边 → 停这一列
                         # 站得不近 → 停掉全部正在跑的车（列车早跑远了，不该卡死在这里）
/train stop <矿车UUID>   # 控制台 / 运维用
/train info              # 站点数、路线数、正在跑几列
```

### 1.6 动力

跟普通矿车一样：**车头那台动力矿车要烧煤**（右键塞煤），或者轨道铺成**通电的动力铁轨**。
没燃料也不在通电动力铁轨上时，列车停下并提示「动力矿车没燃料了，加点煤炭或铺一段通电的动力铁轨吧。」

## 2. 实现要点

### 2.1 为什么连接关系要插件自己记

`org.bukkit.entity.Minecart` **没有实现** `io.papermc.paper.entity.Leashable`（26.3 的
`AbstractMinecart` 继承链里没有 `Leashable`），所以**原版拴绳拴不住矿车**，也不会有
`PlayerLeashEntityEvent`。连接关系完全存在插件的两张表里：

- 内存：`TrainManager.towardFront`（`Map<后车UUID, 前车UUID>`）
- 落盘：`plugins/train/consists.yml`，形如

```yaml
28c4f782-5c09-476a-a00e-0bb2b90990c2: a33255e4-e996-4554-8834-d297249bd7d6
a33255e4-e996-4554-8834-d297249bd7d6: 01244ac5-5d15-4395-b95d-ad0769a25e51
01244ac5-5d15-4395-b95d-ad0769a25e51: 9e4e2fc3-81ab-42ae-a471-9e94f20eef2c
```

（后车指向前车，一路读到没有前车的那台就是队首。）

### 2.2 ★ 位置驱动：26.3 的矿车会吃掉 `setVelocity`

这是本项目最关键的一条。**26.3 矿车走新的轨道运动模型**（`NewMinecartBehavior`），
插件每 tick `cart.setVelocity(0.34, 0, 0)` 之后，原版轨道逻辑与摩擦会在下一 tick 把它
压到 `1e-8` 量级 —— 车纹丝不动，但插件日志一切正常。

实测证据：`train stop` 后手动 `data merge entity <车头> {Motion:[-0.34d,0,0]}`，2 秒后
`Pos` 从 `254.43` 走到 `247.02`（**外部写 Motion 是生效的**）；而在 `train start` 期间
连续采样，`Motion` 读回只有 `-3.6e-8 ~ -2.4e-9`，`Pos` 完全不变。

所以 `TrainDriver.step()` 不用速度推车，改用**弧长推进 + 直接定位**：

```java
drive.progress = Math.min(total, drive.progress + speed * tickInterval);
Vector target = pointAt(drive.path, drive.progress);
moveCart(headCart, target);          // teleport + setVelocity(new Vector())
placeCarsBehind(drive, headCart, target, config.carSpacing());
```

`rebuildPath()` 里**必须** `drive.progress = 0.0;` —— 换段之后不清零，车会以为自己已经
走到新路径的中间，直接跳过一段。

### 2.3 ★ 车厢位置必须用「铁轨方块中心链」

第一版按「车头实际浮点坐标沿轨迹往回退」算车厢位置。车头只要偏离中线一点
（原版矿车会左右微调 ±0.03），算出来的点就落到铁轨外，车厢被判脱轨、**掉到 y=-60**；
前后车越拉越远，最后车头孤零零留在原地、`train info` 显示「行驶中 0」。

现在用 `RailPath.behindChain(world, here, onward, count)`：从车头所在铁轨方块出发，
沿铁轨逐格往回走，每步挑一个既不是「前进方向」也没走过的邻格，返回**方块中心**折线
（`(x+0.5, y+0.0625, z+0.5)`）。第 i 节取 `pointAt(chain, spacing * i)`，
两格之间插值时 **y 取较近那一格的轨面**（避免坡道插出半格高、矿车卡半空）。

### 2.4 寻路

`RailPath.find()` 在铁轨上做 BFS，只走 `Rail` 方块，按 `Rail.getShape()` 决定邻格：

| 形状 | 两个邻格（`{dx, dy, dz}`） |
|---|---|
| `NORTH_SOUTH` / `EAST_WEST` | 两端水平 |
| `ASCENDING_*` | 低端接水平邻居、高端接 `y+1` |
| `SOUTH_EAST` 等四种弯 | 各自两向 |

搜到 `route.max-search-blocks`（默认 96）个方块还没找到就放弃并停下列车，
避免在大路网里把主线程卡住。

### 2.5 到站减速

```java
double remaining = Math.max(0, total - drive.progress);
if (remaining <= config.stopRadius()) { 到站 }
double speed = config.travelSpeed();
if (remaining < config.brakeDistance()) {
    double ratio = remaining / config.brakeDistance();          // 0..1
    speed = config.approachSpeed()
        + (config.travelSpeed() - config.approachSpeed()) * ratio;
}
```

实测速度曲线（`brake-distance: 14`，进站速度 `0.12`，巡航 `0.34`）：

```
6.77 → 6.44 → 5.81 → 4.82 → 3.79 → 2.86 → 1.84 → 0
```

从距站约 12.75 格开始降速，停在 `254.53`（东站 255 前 0.47 格）。

### 2.6 双向列车

非循环路线跑完最后一站时 `flipHead()`：把 `Drive` 的 key 从当前车头换成另一端那台
动力矿车，`direction` 取反，再 `rebuildPath()`。

```java
drives.remove(old);
drives.put(other, drive);   // ← 这里换 key，是 /train stop 找不到车的根源，见 §3
```

### 2.7 保活

- 实体本身：动力矿车/普通矿车由玩家自己放置，插件不新建，也不设 `setPersistent(false)`。
- 编组：`consists.yml` 每 tick `prune()` 时**只在内容变化时**才落盘（避免每 tick 写盘）。
- `prune()` 有个 1 秒宽限期：拿不到实体先记 `missing` 计数，连续 `MISSING_GRACE_TICKS = 20`
  次（约 1 秒）才删。**不能一取不到就删** —— 刚开服区块还没加载，会把整份编组抹掉。
- 车厢被拆/炸掉：`VehicleDestroyEvent` / `EntityRemoveEvent` → `dissolve()` 解散整列。

## 3. 踩过的坑

1. **`setVelocity` 在 26.3 矿车上无效**（§2.2）。凡是「插件算好了速度但车不动」，
   先怀疑这条，别去查燃料、区块、路径。
2. **车厢用浮点轨迹定位会掉到 y=-60**（§2.3）。必须用方块中心链。
3. **`/train stop` 原来只找玩家身边 6 格的矿车**，列车一跑起来就不在脚边了，
   于是永远回「附近没有矿车」。现在站得远就按「停掉全部」处理。
4. **`stop` 只按 `headOf()` 删 `drives` 的 key 不行**：双向列车跑到一半时 `Drive` 挂在
   另一端的动力矿车上，`headOf()` 给的是「当前该用哪个车头」，两边不一致就删不到。
   现在沿 `consistOf()` 找「哪一节正被某个 Drive 当 key」。
5. **`prune()` 一取不到实体就删**，刚开服区块未加载时会清空整份编组（§2.7）。
6. **`/train route create` 曾经把 `loop` 写死为 true**，导致永远建不出往返路线，
   而掉头只在非循环路线上触发 —— 「双向列车做不出来」的真因在这里，不在 `flipHead`。
7. **`editor` 工具改 CRLF 文件要把 `old_string` 写到换行边界**，否则会把下一行拼进同一行
   （`plugin.yml` 的 `usage:` 和 `permission:` 就被拼过一次，导致插件加载失败）。
8. **`getLogger().info("[train] ...")` 会打出 `[train] [train] ...`** —— 插件名前缀已由
   logger 提供，别再自己写一遍。

## 4. 测试与验证

### 4.1 测试轨道

主世界 `x 200..260, z 200` 一条东西向直线（`y=100` 是铁轨，两侧铺实心石头方便站人）：

```
fill 196 99 195 268 99 210 minecraft:stone
fill 196 100 195 268 100 199 minecraft:stone
fill 196 100 201 268 100 210 minecraft:stone
fill 199 100 200 261 100 200 minecraft:rail
```

站点：`西站 (205,100,200)` / `东站 (255,100,200)`，各停 8 秒。
路线：`试验线`（循环）、`往返线`（往返）。

### 4.2 验收记录

| 项 | 结果 |
|---|---|
| 连接三节（`furnace→c1`，再 `c1→c2`） | ✔ 聊天逐条确认「列车现在有 N 节车厢」，拴绳 4→2 |
| 动力矿车夹在中间 | ✔ 提示「动力矿车只能挂在列车的最前面或最后面。」 |
| 自动驾驶逐站停靠 | ✔ 16 秒节拍循环：「到站：西站 停靠 8 秒」→「到站：东站 停靠 8 秒」 |
| 进站减速 | ✔ `6.77 → 6.44 → 5.81 → 4.82 → 3.79 → 2.86 → 0` 格/秒 |
| 精确停在站点 | ✔ 停在 `254.53`（东站 255 前 0.47 格）、`206.5`（西站 205 后 1.5 格） |
| 双向列车掉头 | ✔ `9e4e` 与 `28c4` 两台动力矿车轮流当车头，车头 x 与车尾 x 的大小关系会翻转 |
| 编组跨重启 | ✔ `consists.yml` 原样保留，重启后 `train info` 正常、车厢仍在轨面上 |
| 解开返还拴绳 | ✔ 手上 1 根 → 连接后 0 根 → 解开后回到 1 根（`Inventory` 里 `minecraft:lead`） |
| 破坏解散 | ✔ 拆掉一节车厢 → 整列解散，`train info` 回「行驶中 0」 |
| `/train stop` | ✔ 站得远也能停：`train info` 立刻回「行驶中 0」，车头 x 采样不再变化 |
| 燃料耗尽 | ✔ 提示「动力矿车没燃料了…」，车停住而不是消失 |
| 通电动力铁轨供能 | ✔ `RedstoneRail.isPowered()` 放行，不判「没燃料」 |

### 4.3 观测手段

玩家不在 48 格内时插件的 `sendMessage` 发不出去，所以 `notifyNearest` 会**先打一行日志**：

```
[train] 到站：东站 停靠 8 秒（车头在 254,100,200）
```

`server\.testrun\logs\latest.log` 里 `[train]` 开头的行是最可靠的观测手段。
测速度用 `plugmc/scripts/_trainspeed.py <UUID> <秒数>`（复用一条 RCON 长连接，
按固定间隔采样，不受每次起进程的延迟影响）。

## 5. 配置（`plugins/train/config.yml`）

```yaml
enabled: true
limits:
  max-cars: 12              # 一列最多几节
  tick-interval: 1          # 调度间隔（tick）
  car-spacing: 1.05         # 车厢间距（格）
  free-in-creative: true    # 创造模式不扣不给拴绳
  max-fuel-per-cart: 0      # 0 = 插件完全不补燃料，纯靠玩家加煤
speed:
  travel: 0.34              # 巡航速度，格/tick（0.34 ≈ 每秒 6.8 格）
  approach: 0.12            # 进站最低速度
  brake-distance: 14.0      # 距站点多少格开始减速
  stop-radius: 1.1          # 离站点这么近就认定到站
station:
  default-dwell-seconds: 8  # 新站点默认停靠秒数
route:
  max-search-blocks: 96     # 寻路搜索上限
effects:
  link-particles: true      # 用粒子画出车厢之间的绳子
```

数据文件：`plugins/train/stations.yml` / `routes.yml` / `consists.yml`。
