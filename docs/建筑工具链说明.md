# AI 建筑生成：本服选型结论

> 面向服务器：Paper 26.3（线上实例 `bb911bbb`，Linux 容器）/ 原版客户端零安装直连
> 依据：`Minecraft-AI建筑生成项目调研.md`（128 行 / 6 章）+ 本机与测试服实测
> 成文时间：2026-11-13

---

## 0. 一句话结论

**外部 AI 建筑项目一个都不要直接装。** 本服唯一可行路径是：

> **AI 只产「蓝图 JSON」→ 本地确定性展开成 26.3 原版 `.nbt` 结构文件 → 放进数据包 → `/place template` 落地**

这条路径已经全线跑通，四个环节各有交付物：

| 环节 | 工具 | 状态 |
|---|---|---|
| 蓝图 JSON / 预设 → `.nbt` | `plugmc/scripts/blueprint_to_nbt.py` | ✓ 实机落块 30/30 命中 |
| 落地前先看比例配色（不开游戏） | `plugmc/scripts/preview_structure.py` | ✓ 单结构 / 整张清单都能渲染 |
| 单座建筑放到指定位置 + 校验 | `plugmc/scripts/place_template.py` | ✓ 线上 API / 本机 RCON 双通道 |
| 整片街区按清单批量摆 + 校验 | `plugmc/scripts/place_plan.py` | ✓ 示例广场 8 项 52/52 命中 |
| 打包分发 | `plugmc/datapacks/plugmc-structures/` | ✓ format 121，`gradlew :datapacks:buildDatapacks` |

## 1. 本服的硬约束（决定了什么能选）

| # | 约束 | 对选型的直接后果 |
|---|---|---|
| C1 | 玩家**零安装**直连（不装 mod、不手动下资源包） | 任何"客户端 mod"路线直接出局；只认服务端命令 / 插件 / 数据包 |

## 2. 候选筛选结果

### 2.1 图生方向（报告里真正的两条）

| 候选 | 本服可用性 | 判定 |
|---|---|---|
| **`RikkaLove0721/Image-to-MC`** | 目标版本 **1.12.2**、导 **`.schematic`**（WorldEdit 格式）、要 **Windows + WebView2**、0 star / 无 license | ⚠ **只借它的"蓝图 spec 思路"，不借它的产物** |
| **`AugustZhang1/AI-Builder-Minecraft`** | **硬要 RCON**（C3 出局）、要求**与 MC 同机**、要 OpenSCAD + Docker | ❌ 出局 |

**关于 Image-to-MC 的正确用法**：它最有价值的部分不是代码，而是**蓝图 JSON 的数据结构**——
`palette{wall,trim,roof,glass,accent}` / `volumes[]{x,y,z,w,h,d,mat,floors}` / `windows[]{face,u,v,w,h,cols,rows,gap_u,gap_v,mat,frame}` / `roof{type,parapet,mat}` / `details[]`。
这套结构只描述"体量 + 开窗 + 屋顶 + 细节"，方块由本地展开——**正好适合我们自己做转换器**。

它的 `.schematic` 产物不能直接用，两个原因：
1. 1.12.2 的数字 ID + metadata 需要版本转换，26.3 早就没有数字 ID；
2. 本服**没装 WorldEdit**（C4），而 WorldEdit 7.4.6 的 `BuiltInClipboardFormat` 枚举实测只有 5 种（`MCEDIT_SCHEMATIC` / `SPONGE_V1~V3` / `SPONGE` / `SPONGE_SCHEMATIC`），**根本没有原版 structure `.nbt` 的读写器**。

### 2.2 文生方向

| 候选 | 本服可用性 | 判定 |
|---|---|---|
| **`brissach/probuild`** | **不含预训练权重**（无 checkpoint 时 `503 MODEL_UNAVAILABLE`）、palette 只有 16 种方块、结构边界 32³、要求 `Paper 1.21+` / JDK 21+ / Python 3.11+、**PolyForm Noncommercial**（不可商用） | ⚠ **架构值得抄，插件不能用**——它的"插件 + 后端 + HMAC 签名"这套太重在 4 人小服上；16 种方块做不了主城 |
| 其余 11 个文生项目 | 报告里均无"可在 Paper 26.3 上跑 + 无 RCON + 无客户端 mod"的同时满足 | ❌ 不采用 |
| HuggingFace 上的建筑权重 | **没有公开的建筑生成权重**（报告已核实） | ❌ 无货 |

### 2.3 最终选型

> **不装任何现成项目。自建「蓝图 JSON → 26.3 `.nbt`」转换器，AI 负责写蓝图 JSON。**

理由：
1. 这是唯一同时满足 C1–C7 的路径——它**不引入任何运行时依赖**，转换是离线的，产物是原版数据包；
2. 蓝图 JSON 人也能写、AI 也能写，出错时好定位（不像模型输出那样不可预期）；
3. 产物是原版 `.nbt`，**不依赖 WorldEdit / 不依赖 RCON / 不影响既有 282 MB 世界**；
4. 已实测跑通（见 §3）。

## 3. 已实测通过的技术点（可直接复用）

### 3.1 26.3 原版结构文件格式（`javap` + 解压原版 jar 取证）

- 目录：`data/<namespace>/structure/<name>.nbt`，**单数 `structure/`**（原版 jar 内实有 1710 个条目）。
- 文件是 **gzip 压缩的 NBT**。
- 根节点：`TAG_Compound` + 空名字，**必须先写标记字节 `0x0a`**（少了它会报 `There is no template with ID "..."`，而不是"NBT 非法"，极易误判）。
- 根键：`size`(int×3) / `entities`(空 list) / `blocks`(list) / `palette`(list) / `DataVersion`(int)。
- `blocks[]` 每项 `{pos:[x,y,z], state:<int 下标>}` —— **`state` 是 palette 下标整数**。
- `DataVersion` 在 26.3 是 **5023**（= `world_version`）。

### 3.2 ★ palette 的键名是 `id` / `properties`（全小写）——最大的坑

实测原版 `data/minecraft/structure/village/plains/houses/plains_big_house_1.nbt`：
```
palette: [ { id: "minecraft:dirt" },
           { id: "minecraft:oak_log", properties: { axis: "y" } }, ... ]
```

而旧版（1.13 时代起一直沿用的）写法是 `Name` / `Properties`（首字母大写）。

**这个坑的表现极具迷惑性**：
- `/place template` **照样回 `Loaded template ... at x, y, z`**（成功消息）；
- 服务端日志**没有任何报错**；
- 但**一个方块都不会落下**。

误判过程实录：先怀疑"区块没加载"（加了 `forceload`，没用）→ 怀疑"无玩家在线不落块"（原版自带结构同样不落，误导）→ 最后对比原版 NBT 的字节布局，才发现 `palette` 里是 `id` 不是 `Name`。

> **转换器修正后立刻生效**：`place template structprobe:lamp3 525 -60 525` → 石砖底座 / 3 格橡木栅栏 / 灯笼**全部按坐标落到位**。

### 3.3 `/place template` 的真实能力（`javap` 读 `PlaceCommand.class`）

```
place template <template> [pos] [rotation] [mirror] [integrity] [seed] [strict]
place structure <structure> [pos]
place jigsaw <pool> <target> [max_depth] [position]
place feature <feature> [pos]
```

- `rotation` / `mirror` / `integrity` / `seed` 都可用 —— **同一个 `.nbt` 能摆出多种朝向**，这对主城布景很省事。
- 前提：目标区块必须已加载（`checkLoaded`），否则命令直接失败；控制台执行前先 `forceload add`。

### 3.4 验证"到底落没落块"的正确方法

`execute if block ... run say ...` **永远不会有 RCON 回显**（`say` 是广播，不回给发送者）——这一点导致过多次误判。

两个可靠判据：
1. `execute if block <x> <y> <z> <block> run seed` → 命中时回 `Seed: [...]`，不命中时**无输出**；
2. `fill <区域> minecraft:air replace <方块>` → 回 `Successfully filled N block(s)`，**这就是计数**。

## 4. 主城 / 装饰的落地路径

### 4.1 工具链

```
AI（或人手）写 蓝图 JSON
   ↓  plugmc/scripts/blueprint_to_nbt.py
26.3 原版 .nbt 结构文件
   ↓  放进数据包 data/<ns>/structure/
/place template <ns>:<name> <x> <y> <z> [rotation] [mirror]
   ↓
世界里的方块（真实方块，可被玩家正常破坏/保护/记录）
```

### 4.2 已内置的预设（可直接用）

| 预设 | 内容 | 方块数 | 文件大小 |
|---|---|---|---|
| `lamp_post` | 石砖底座 + 3 格橡木栅栏 + 灯笼 | 5 | 198 B |
| `bench` | 2 个橡木台阶 + 2 个橡木活板门 | 4 | 221 B |
| `fountain` | 3×3 石砖池 + 中心水柱 + 四角海晶灯 | 15 | 228 B |
| `house` | 9×5×7 两层木屋：石砖基座 + 木墙 + 24 块玻璃窗 + 45° 深色橡木四坡顶 + 室内灯笼 | 523 | 1675 B |

`house` 走的是**体量展开**路径（`volumes / windows / roof / details`），四个装饰件走的是**方块清单**路径，转换器自动判别。

命令行：
```powershell
# 方块清单预设
python scripts\blueprint_to_nbt.py --preset lamp_post --out <路径>\lamp_post.nbt
# 体量展开预设
python scripts\blueprint_to_nbt.py --preset house --out <路径>\house.nbt
# 自己写的蓝图 JSON
python scripts\blueprint_to_nbt.py --spec my_house.json --out <路径>\my_house.nbt
```

### 4.3 蓝图 JSON 的写法（体量展开）

```json
{
  "name": "my_house",
  "palette": {
    "wall":  "minecraft:oak_planks",
    "trim":  "minecraft:stripped_oak_log",
    "roof":  "minecraft:dark_oak_stairs",
    "glass": "minecraft:glass",
    "floor": "minecraft:oak_planks",
    "base":  "minecraft:stone_bricks",
    "light": "minecraft:lantern[hanging=false]"
  },
  "volumes": [
    {"x":0,"y":0,"z":0,"w":9,"h":5,"d":7,"floors":2,
     "base_mat":"base","lit":true,"floor_mat":"floor","ceiling_mat":"floor"}
  ],
  "windows": [
    {"face":"south","u":1,"v":1,"w":2,"h":1,"cols":2,"rows":2,"gap_u":3,"gap_v":1}
  ],
  "roof": {"type":"hip","mat":"roof","overhang":1,"step":1},
  "details": [
    {"type":"door","face":"south","u":4,"h":2,"w":1},
    {"type":"pillar","mat":"trim","at":[[0,0],[8,0],[0,6],[8,6]]}
  ]
}
```

要点（全部是实测踩出来的）：

- `face` 取 `north/south/east/west`，`u` 是沿墙面方向的格子序号，`v` 是离地高度；
- **窗户格子小于 3×3 就不画框**（`has_frame = cell_w >= 3 and cell_h >= 3`），窄窗一律用实心 `glass` —— 用 `glass_pane` 会因为玻璃板互相连接在客户端拼成"十"字；
- **屋顶 `step` 是每层内收的格数**，`step: 1` 就是 45°。9 格宽的房子如果设 `step: 1` 会叠 5 层、和楼体一样高，那是正常坡度不是 bug；想更平就 `step: 2`；
- 屋顶每层**必须铺满实心**（不是只画一圈边框），否则圈内会露出天花板，俯视是个坑；
- `base_mat` 会在地板下再铺一层；`lit: true` 会在每层楼板中间放 `light`。

### 4.4 主城建议的推进顺序

1. **先做"模块化装饰件"**（路灯 / 长椅 / 喷泉 / 花坛 / 摊位 / 指示牌）——单个 5–30 方块，`/place template` 一把一个，几乎不可能出错；
2. **再做"单体建筑"**（一座房子 / 一座塔）——用上面那套 `volumes + windows + roof` 描述，转换器负责展开；
3. **最后做"街区级布景"**——把前两步的模块拼成一张"摆放清单"（坐标 + 模板名 + 朝向），批量执行。

这样每一步都能单独验证，出问题只影响一个模块，不会污染既有 282 MB 世界。

### 4.5 落地三步（每座建筑都走这三步）

```powershell
# 1) 生成 .nbt（或直接从预览确认比例）
python scripts\blueprint_to_nbt.py --spec my_house.json --out datapacks\plugmc-structures\data\plugmc\structure\my_house.nbt

# 2) 先看效果——纯本地渲染，不开游戏、不占窗口
python scripts\preview_structure.py datapacks\plugmc-structures\data\plugmc\structure\my_house.nbt --out preview.png --view all

# 3) 打包上传（本机测试服）或走线上部署，然后放置 + 校验
python scripts\place_template.py --local --template plugmc:my_house --at 100 -200 --ground --local-nbt ...\my_house.nbt --samples 24 --reload
```

`place_template.py` 的关键行为：

- **`--reload`**：换过数据包文件（重新打了 zip）必须加。不加的话服务端用的还是内存里的旧模板，会一直把上一版结构放一遍 —— 实测表现为"墙体全对、屋顶整片 MISS"，很容易误判成转换器有 bug；
- `--ground`：自动向下找地面。找之前会先 `forceload add`，否则 `execute if block` 静默返回 false，会把"最高处"当成地面；
- 落块校验用 `execute if block ... run seed`，**不能用 `run say`**（say 是广播，永远没有 RCON 回显）；
- 返回码 `0` 全中 / `1` 部分未中 / `2` 全未中。全未中优先怀疑结构文件的 palette 键名。

### 4.6 拼街区：摆放清单 + `place_plan.py`

单体建筑没问题之后，主城就是"一张清单摆一片"。清单是 JSON，`plans/plaza.json` 是可直接跑的示例：

```json
{
  "anchor": [1000, 1000],
  "floor": {"x0": 992, "z0": 992, "x1": 1011, "z1": 1017,
            "mat": "minecraft:stone_bricks", "depth": 1},
  "defaults": {"samples": 12, "reload": true},
  "items": [
    {"template": "plugmc:fountain", "at": [999, 999], "ground": true},
    {"template": "plugmc:bench", "at": [997, 1001], "ground": true, "rotation": 90},
    {"template": "plugmc:house", "at": [998, 1009], "ground": true}
  ]
}
```

```powershell
python scripts\place_plan.py --plan plans\plaza.json --local --dry-run   # 先算不执行
python scripts\place_plan.py --plan plans\plaza.json --local             # 真跑
python scripts\preview_structure.py --plan plans\plaza.json --out plaza.png --view iso  # 不碰服务器先看图
```

三个字段是踩坑踩出来的：

- **`anchor`** —— 整张清单共用同一个地面探测点。**不给 anchor 的话，先放的喷泉、灯柱会被后面的项当成"地面"**，一个广场能摆出三种高度（实测 -60 / -59 / -58）。有了 anchor 只在锚点探一次，全部项目放同一个 y；
- **`floor`** —— 整片铺装，用原版 `fill` 在模块之前铺一层。单次 `fill` 上限 32768 格，超了会报 `Too many blocks in the specified area`；
- **`rotation`** —— 只认 `0/90/180/270`，内部映射成服务端要的枚举名 `none` / `clockwise_90` / `180` / `counterclockwise_90`。**直接给 `place template` 传 `270` 会报 `Invalid value '270'`**（这是 Rotation 枚举的序列化名，不是角度）。

★ **`/place template` 的旋转是绕「放置点」转，不是绕结构包围盒中心转** —— 转了 180° 之后结构会整片长到放置点的负方向。实测 11×9 的房子 `place template ... 998 -60 1009 180`，基座落在 `dx ∈ [-9,-1]`、`dz ∈ [-7,-1]`。所以清单里同一个位置换朝向后，占地会跳到另一侧，摆密集街区时要么留够余量、要么按旋转后的方向补坐标。

### 4.7 增量安全守则（对应 C5）

- **只在未开发区域放**：主城选定区域先 `forceload add` 固定，避免和玩家已建的东西重叠；
- **放置前拍快照**：`/place template` 前用 `Backuper` 手工备份一次（线上目前没装，这是已知缺口 R21）；
- **不要用 `/place structure`**：它会按生物群系做"结构生成"，可能连带地形改造；`/place template` 只放方块，可控得多；
- **`fill ... air replace <方块>` 会真的把方块删掉** —— 用它做材质计数就等于自己拆了刚建的房子，计数和保留不可兼得。

## 5. 不推荐的东西（避免以后重复评估）

| 方向 | 为什么不做 |
|---|---|
| 装 Probuild / AI-Builder-Minecraft 插件 | 前者无权重 + 16 种方块 + 非商用许可；后者硬要 RCON（C3 出局）且需 Docker |
| 用 Image-to-MC 的 `.schematic` 产物 | 1.12.2 数字 ID；且本服没有 WorldEdit，而 WorldEdit 也不认原版 `.nbt` |
| 在服务端跑图像模型 | 4 人小服不值得；线上容器内存只有 3604 MB 上限（`-Xmx3604M`），跑不动 SD 类模型 |
| 端到端"文生建筑" | 报告已核实：HuggingFace 上没有公开权重，现有项目都是"AI 写 spec + 本地展开" |
| 把生成能力做成线上运行时插件 | 建筑生成只有管理员用、频率极低，塞进线上容器只会挤占 3604 MB 内存；本地生成 + 上传才是对的 |
